# Score YAML のインポート

Score YAML を読み込み、通常の Riffra プロジェクトとして編集・保存・再生・レンダリングできる。
楽譜の反復や度数表記はインポート時に演奏イベントへ展開する。以後の編集と演奏は、生成された CreativeSession を正準状態として扱う。

## 読み込みと音源の指定

Desktop のプロジェクトメニューで **Import Score YAML…** を選び、`.score.yaml` ファイルを開く。
外部楽器の Definition が必要な場合は、表示された楽器 ID ごとに JSON ファイルを選択する。
CLI では次のコマンドを使う。実行中の Host への読み込みには `--attach` を指定する。

```bash
riffra project import-score ./song.score.yaml
riffra project import-score ./song.score.yaml --bind lead=./lead/definition.json
```

`--bind` は楽器ごとに繰り返し指定できる。バインドは `external: true` の楽器だけに指定する。
Definition の相対パスは Score ファイルのディレクトリを基準に解決する。
プリセットは Score の上位ディレクトリにある `presets/CATEGORY/NNN-name/definition.json` を参照し、
参照元がない場合は同梱カタログの対応する ID を利用する。

読み込みに成功すると、新しいプロジェクトを作成して有効化する。
解析や音源検証に失敗した場合は、元のプロジェクトを継続して使用できる。

## 演奏内容の対応

Score の解析と展開は Runtime の `score/` が行い、`score_yaml_import.rs` が正準データへ変換する。
下表の演奏に関わる情報は保存後も Native Audio Engine へ投影される。

| Score の情報                                               | Riffra での表現と動作                                                                                                                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PPQ・分数拍                                                | Score の PPQ と整数 Tick を保持する。既定の新規プロジェクトは 960 PPQ                                                                                                    |
| テンポ・拍子の変更                                         | ProjectTimebase の変更点として保持し、表示・スナップ・サンプル位置の変換で共有する                                                                                       |
| メロディ・ドラム・コード・反復                             | Score の展開結果を MidiNote に変換する。音高・開始位置・長さ・ベロシティを保持する                                                                                       |
| 複数レーン                                                 | レーンごとに Instrument Track と楽曲全体を覆う MIDI クリップを生成する。同じ楽器のレーンも独立した音源インスタンスで演奏する                                             |
| サステイン・ピッチベンド・モジュレーション・アフタータッチ | InstrumentControlEvent として精度を保ち、同 Tick の優先順位とソース順で実行する                                                                                          |
| ParameterChange・ParameterRamp                             | 音源のパラメータ定義で検証する。ランプはテンポ変更を含む開始・終了 Tick のサンプル位置から長さを求め、処理ブロックをまたいで継続する                                     |
| PartWindow                                                 | 展開済みの音符範囲を保持し、区間境界に演奏制御のリセットを追加する。パラメータは音源定義の既定値へ戻す                                                                   |
| Preset・Definition・External・Sample                       | 音源と参照ファイルを解決する。保存リソースは共有し、演奏状態はトラックごとに分離する                                                                                     |
| ゲイン・パン                                               | レーンゲインを維持し、パンには中央の左右ゲインを保つ線形バランス方式を使う。編集用フェーダーの操作範囲は保存値を制限しない                                               |
| セクション別ゲイン                                         | Track Volume Automation に実効音量を保持し、境界から指定秒数で振幅を線形補間する。Score では 5 ms の遷移を使う                                                           |
| 外部音声入力                                               | 参照パートの全レーンを入力元として登録する。ゲイン・パン適用後の音声を遅延補正して合算する。入力先の各レーンは同じ合算音声を受け取る。モノラル楽器には左右を平均して渡す |
| マスタリング・フェード                                     | MixdownSettings にラウドネス・True Peak の目標とフェード時間を保持する。LRA 目標は任意の測定・警告条件として扱う                                                         |
| セクション                                                 | 各出現を独立した TimelineRegion として保持する                                                                                                                           |
| 和声                                                       | Score の主音とコード構成音を HarmonyEvent に投影する。和声イベントは編集・参照用であり、展開済みの音符を再生成しない                                                     |
| 元 Score                                                   | ScoreSource にファイル名と元 YAML 全文を保持する。元の記法・制作ノート・再利用素材は参照情報として保存する                                                               |

## 保存と再利用

同梱プリセットと Definition・アセットの内容が一致する場合は、同梱リソースを利用する。
それ以外の音源は Data Root 内のプロジェクト音源スナップショットへコピーする。
Definition 本体と実際に参照するアセットだけを収集し、保存先を基準とする参照に書き換える。パッケージ外の参照も収集対象とし、同じディレクトリにある無関係なファイルは保存しない。
参照先にシンボリックリンクや読み込めないリソースがある場合はエラーにする。
同じ Definition を使う複数のレーンはスナップショットを共有する。

元の Score・Definition・サンプルを移動しても、保存済みプロジェクトはそれらを参照しない。
`.riffra` のエクスポート・インポートには、音源スナップショットと ScoreSource も含まれる。
元 YAML は参照用として保持し、トラックやクリップの編集によって書き換えない。

時間軸の PPQ を変更すると、既存の音符・制御・範囲・録音位置を新しい PPQ へ換算する。
既存の音楽的位置を整数 Tick で正確に表せない変更は拒否する。
データモデル全体の規則は [data-model.md](data-model.md)、音声実行は [audio-engine.md](audio-engine.md) を参照。
