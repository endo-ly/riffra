# リグ

曲（プロジェクト）とは別に、オーディオ入力からすぐ音を出すための「リグ」を定める。2章が要件、3章がドメインと永続化、4章がランタイムと命令、5章がRust・C++の境界、6章が音声エンジン、7章が画面、8章がテスト、9章が文書である。

## 1. 目的

AIが同じセッションで曲を組んでいる横で、利用者が曲と関係のない演奏をすぐ始められるようにする。いつも使う音作り（入力とエフェクトの並びとプラグインの状態）を保存しておき、上部バーから数クリックで鳴らす。左列を閉じていても使える。

リグはプロジェクトに属さない。セッションに入らないので、AIからは見えず、undo/redoの履歴にも入らない。

## 2. 要件

| 項目           | 内容                                                                                    |
| -------------- | --------------------------------------------------------------------------------------- |
| 中身           | 名前、オーディオ入力チャンネル1つ、エフェクトの並び（VST3、状態・バイパスを含む）、音量 |
| 入力           | オーディオ入力だけ。MIDI入力と音源は持たない                                            |
| 同時に鳴らす数 | 1つ。別のリグを鳴らすと入れ替わる                                                       |
| 保存           | 変更はその場で保存する。保存ボタンはない。ネイティブエディターでの変更も保存される      |
| 鳴る条件       | トランスポートと無関係に鳴る。プロジェクトの切替でも止まらない                          |
| 起動時         | 何も鳴らさない（前回鳴らしていたリグを自動で再開しない）                                |
| エディター     | リグを鳴らしても自動では開かない。利用者が開く                                          |
| 録音           | しない                                                                                  |
| 音色の切替     | 専用機能は持たない。リグを複製して別のリグとして持つ                                    |

## 3. ドメインと永続化

### 3.1 ドメイン（`riffra-core`）

```text
Rig {
  id: RigId,
  name: String,
  audio_input: AudioInputRoute,     // トラックと同じ型
  effects: Vec<EffectDevice>,       // トラックと同じ型
  gain_db: f64,
}
```

- 入力・エフェクトはトラックの型を使い回す。リグ専用の複製型を作らない。
- エフェクトの追加・削除・並べ替え・バイパス・状態更新の規則は、トラックのエフェクトと同じものを共有する。トラック用の処理を写して二重に持たない。
- 編集はセッションの `CreativeSession` とは別の集約として扱い、セッションのrevisionや履歴に触れない。

### 3.2 永続化（`riffra-host`）

- `data_root/rigs/<rig-id>.json` に1リグ1ファイルで保存する。
- 書き込みはセッション保存と同じ原子的な書き方にする。
- 一覧はディレクトリを読んで作る。SQLiteの索引は持たない。

## 4. ランタイムと命令（`riffra-runtime`）

### 4.1 状態

- `HostState` に、いま鳴らしているリグのIDを持つ。プロジェクトの状態とは独立している。
- リグはHostに属し、プロジェクトに属さない。命令はプロジェクトIDを取らない。

### 4.2 命令

GUIとCLIが共有する命令表に載せる。名前の付け方と引数の形は、既存のトラックのデバイス命令に合わせる。

| 命令                                            | 内容                                           |
| ----------------------------------------------- | ---------------------------------------------- |
| `rig.list`                                      | リグの一覧と、鳴らしているリグ                 |
| `rig.create`                                    | 名前と入力を指定して作る                       |
| `rig.update`                                    | 名前・入力・音量の変更                         |
| `rig.duplicate` / `rig.delete`                  | 複製・削除。鳴らしているリグを削除したら止める |
| `rig.effect.add` / `remove` / `move` / `update` | エフェクトの追加・削除・並べ替え・バイパス     |
| `rig.start` / `rig.stop`                        | 鳴らす・止める                                 |
| `rig.editor.open`                               | リグのエフェクトのネイティブエディターを開く   |

リグの変化はGUIへイベントで知らせ、既存の同期の仕組みに乗せる。

## 5. Rust と C++ の境界

```text
Rust（正準）                              C++（実行）
RigStore  data_root/rigs/<id>.json
HostState の鳴らしているリグ  ──RigProjection──▶  RigEngine
                               ◀──リグのプラグイン状態イベント── ネイティブエディター
RigStore へ保存
```

- `RigProjection { rig_id, revision, audio_input_channel, gain_db, effects }`。`effects` は実行グラフの `GraphPluginDevice` と同じ型で、バイパス・欠落したデバイスを落とす規則も実行グラフの投影と共有する。
- サイドカー命令は `OpenRig { projection }`（丸ごと置き換え）、`CloseRig`、`OpenRigEditor { deviceId }`。
- エディターの状態イベントは、リグ専用のイベント（`rigId` と `deviceId` を持つ）にする。プロジェクトの `EffectOwner` にリグを加えない。`EffectOwner` は「プロジェクトの中の持ち主」を表す型だからである。
- Rustはイベントを受けてRigStoreへ保存する。プロジェクトには書かない。

## 6. 音声エンジン（`native/audio-engine`）

- `RigEngine` を `PluginAudition` と同じ層に置く。中身は `PluginRack` と、指定チャンネルの入力監視である。
- プラグインの生成はプラグインのライフサイクル用スレッドで行い、実時間スレッドへは用意済みの状態を受け渡す。
- エフェクトの並びはトラックと同じ `PluginChain` で処理する。
- 新しい投影を受けたとき、同じリグでエフェクトの並び（デバイスIDとパス）が同じならチェーンを使い回し、バイパスだけを適用する。プラグインの状態を変えるのはエディターだけで、エディターは使い回しているインスタンスを直接編集しているため、保存済みの状態を適用し直さない。名前・入力・音量・バイパスの変更や、エディターでの変更の保存では、プラグインを作り直さず、開いているエディターも閉じない。そのため、リグの投影はバイパスしたエフェクトも含める。
- リグが変わったときや並びが変わったときはチェーンを作り直す。その前にエディターを閉じ、最終状態をRustへ取り込んでから投影する。
- Rustは鳴っているリグを投影する前に、保存待ちのエディターの変更を取り込む。バイパスはRustが持ち、エディターの状態イベントでは変えない。
- ミックスの位置は、セッションのマスター音量の後、ソフトフェードとリミッターの前にする。リグは曲の一部ではないので、曲のマスター音量とマスターエフェクトの影響を受けない。
- フィードバック保護の対象に含める。

## 7. 画面（`apps/desktop`）

`GlobalControlBar` のundo/redoの後ろに、区切り線を挟んで置く。undo/redoはプロジェクトの操作なので、プロジェクトとリグの間には置かない。

| 状態           | 表示                                                                                                                                                                                                      |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 停止中         | アイコンと「リグ ▾」の小さなボタン                                                                                                                                                                        |
| 鳴らしている間 | プロジェクトと同じ2段表示（上：リグの名前、下：入力）、▾、⧉（エディターを開く）、■（止める）。名前は最大160px程度で省略する                                                                               |
| ▾ を開いたとき | リグの一覧（押すと鳴らす）。鳴らしているリグはその場で展開し、エフェクトの並び（バイパス、⧉、削除）、エフェクトの追加（プラグインの検索）、入力、音量、名前の変更、複製、削除を出す。末尾に「新しいリグ」 |

- 入力メーターはバーに置かない。右側の In で足りる。
- リグの入力と同じ入力を曲のトラックが監視しているときは、▾の中に「In 1 はトラック "Gtr" でも監視中」と出す。自動で止めることはしない。
- 色・余白はRootのデザイントークンを使う。

## 8. テスト

- Rust：リグの編集規則、RigStoreの読み書き、命令の振る舞い（鳴らす・止める、鳴らしているリグの削除、エディターの状態が保存されること）、投影。
- C++：投影の検証、インスタンスの使い回し、ミックスの位置、フィードバック保護。
- Desktop：上部バーの3つの状態と、▾の中の主な操作。

## 9. 文書

実装後、`docs/` の該当箇所（構成、データモデル、IPC、音声エンジン、画面設計）に、リグについて永続化すべき事実を反映する。
