# 作曲の手順（Score YAML による設計と実装の分業）

曲は Score YAML 1ファイルを正本として作る。打ち込みの方法はこれだけで、Python などで打ち込みを自動化するスクリプトは作らない。
作業は**設計**（何を鳴らし、どんな音であってほしいか）と**実装**（それをどの音源・音作り・ミックスで実現するか）に分け、別の担当が受け持てるようにする。

## 正本と置き場

```
library/
├─ instruments/<name>.yaml   # 再利用する音源テンプレート
├─ effects/<name>.yaml       # 再利用するエフェクトテンプレート
└─ states/<name>.json        # テンプレートが参照する VST3 の状態
music/<曲>/
├─ score.yaml        # 正本。設計も実装もこの1ファイルに書く
├─ sounds/           # 自作の内蔵音源（definition.json と素材）
├─ states/           # この曲だけで使う VST3 の状態ファイル
├─ audio/            # 録音・効果音
└─ renders/          # 最新の書き出し
```

- スコアは上位ディレクトリの `library/` を自動で探す。`source.use` / `effects[].use` は `library/instruments` / `library/effects` の名前を参照する
- ライブラリのテンプレートは再利用する設定の正本であり、曲ごとの差分だけを `score.yaml` に書く。曲側で `state` を置き換えた場合は、テンプレートの `patch` を引き継がない
- `use` にパスや拡張子は書かない。相対パスは、その値を書いた YAML ファイルを基準に解決する

- Riffra のプロジェクトは `score.yaml` から作られる派生物として扱う。GUI で直した内容も `score.yaml` へ戻す（GUI→YAML の自動反映は計画中。それまではエージェントが書き戻す）
- 内蔵音源: `preset` / `definition` で指定する音源。用意されたものも自作のものも含む
- 読み込み: MCP `project` の `import_score`、CLI `riffra project import-score <path> [--attach]`
- 読み直し: MCP `project` の `rebuild_score`、CLI `riffra project rebuild-score [--path]`。Live Host では保存を検知して自動で更新される
- 検証: `riffra score validate <path>`（音源の解決まで確かめる）と `sonalloy score validate <path>`（内蔵音源だけで鳴らせるか確かめる）。展開結果は `riffra score inspect` と `sonalloy score inspect` で確認する

## 担当

| 担当 | 受け持つこと                                                                           | 受け持たないこと               |
| ---- | -------------------------------------------------------------------------------------- | ------------------------------ |
| 設計 | 構成・和声・リズム・旋律・低音・編曲・表情。各パートの**欲しい音を自然言語で定義する** | 音源の選定、音作り、ミックス   |
| 実装 | 欲しい音を満たす音源の選定と音作り、奏法の対応、ミックス、マスタリング、検証           | 音符・和声・リズム・構成の変更 |

## 設計

| #   | フェーズ   | 決めること                                           | 書く項目                                                                  | 終わりの条件                                            |
| --- | ---------- | ---------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------- |
| D1  | 骨格       | 曲の核、長さ、エネルギーの起伏、テンポ・拍子・調     | `meta`（bpm・拍子）、`form`、`time_changes`、`notes`                      | セクションの並びと長さが決まり、起伏を `notes` に書いた |
| D2  | 和声       | 進行、転調、コードチェンジの拍、食い                 | `chords`、`chord_changes`                                                 | 全小節に和声がある                                      |
| D3  | リズム     | 拍の骨格、細分、ノリ、パート間のずれ                 | `drums`、`comp`、`swing`、`timing_offset_steps`                           | 拍の骨格が全セクションで鳴る                            |
| D4  | 旋律・低音 | 主旋律、低音、対旋律、アルペジオ                     | `melodies`、`lines`、`arps`、`counters`                                   | 主旋律と低音が通して鳴る                                |
| D5  | 編曲・表情 | 各パートの出入り、強弱の流れ、奏法、演出             | `placements`、`events`、セクションの `velocity`、奏法記号                 | 全区間の出入りと強弱が書けている                        |
| D6  | 発注       | 各パートの欲しい音、セクションごとの主役、完成の条件 | `instruments.<id>.role` / `sound`、`sections.<名前>.notes`、`meta.master` | 実装担当が質問せずに着手できる                          |

- D1〜D5 は行き来してよい。順番は依存関係の目安であり、旋律が軸の曲なら D4 を先に仮置きしてよい

### 発注（D6）に書くこと

- **欲しい音**（`sound`）: 質感、明暗、距離、アタックと減衰、帯域の居場所、年代感、隣のパートとの関係、避けたい音。音源名・プラグイン名・プリセット名は書かない
- **役割**（`role`）: そのパートが曲の中で何をしているか
- **セクションごとの主役**（`sections.<名前>.notes`）: どのパートが前に出て、どのパートが支えるか
- **完成の条件**: ラウドネスの目標（`meta.master`）、セクション間の音量の起伏、必ず聴こえるべきもの

## 実装

| #   | フェーズ       | すること                                                                                                 | 書く項目                                                                |
| --- | -------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| I1  | 音源の選定     | 欲しい音を満たす音源を選ぶ。VST3、ライブラリの音源、内蔵音源(Sonalloy)(プリセット、自作)のどれでもよい。 | `instruments.<id>.source`・`kit`、`kits`、`sounds/`、`states/`          |
| I2  | 奏法の対応     | 奏法・制御を音源のキースイッチ・CC に対応させ、ベロシティの効き方の差を補正する                          | `source.velocity`（奏法ごとの `articulations` は未実装）                |
| I3  | 音作り         | 楽器ごとのエフェクトとパラメーター。歌声の全体パラメーター                                               | `effects`、`source.vst3.state` / `patch` / `params`（VoiSona は未実装） |
| I4  | ミックス       | ゲイン、パン、バス、センド、サイドチェイン、オートメーション                                             | 楽器の `gain_db` / `pan`、`part_gains`、演奏ごとの `gain_db`、`mix`     |
| I5  | マスタリング   | `meta.master` の目標を満たすマスターのチェイン                                                           | `mix.master`                                                            |
| I6  | 検証と差し戻し | 書き出して測り、発注の完成の条件と照らし合わせる                                                         | —                                                                       |

## 境目のルール

| 項目                                                                                                       | 担当                                 |
| ---------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 楽器の `gain_db` / `pan`、`part_gains`、`lines.*.gain_db`、`placements[].gain_db`                          | 実装                                 |
| `source`、`effects`、`kit`、`kits`、`mix`、`audio` / `audio_clips`                                         | 実装                                 |
| `meta.master`（ラウドネスの目標）                                                                          | 設計（完成の条件。実装担当は満たす） |
| それ以外（構成・和声・リズム・旋律・編曲・強弱・奏法・歌詞・歌の表現・内蔵音源・`sound`・`role`・`notes`） | 設計                                 |

- 実装担当は設計の項目を変更しない
- 音楽の側に原因がある問題（音源の音域外の音、パート同士の帯域の衝突、主役が埋もれる編成）は、直さずに設計へ差し戻す
- 欲しい音を満たせない場合は、満たせない点と代わりの案を添えて差し戻す。黙って近い音で済ませない

### 差し戻しの書き方

```
場所: walk 2回目 3小節目 / lead
問題: 音域外（C6 を含むが、選んだ音源は A5 まで）
理由: 欲しい音「細く硬い撥弦」を満たす候補はこの音源だけ
案: 該当の2音を1オクターブ下げる、または音域の広い音源で質感を妥協する
```

## 聴いたあとの指摘の振り分け

| 指摘の例                                             | 担当                                       |
| ---------------------------------------------------- | ------------------------------------------ |
| 旋律・進行・リズム・構成・出入りに関するもの         | 設計                                       |
| 音色・質感・バランス・空間・音圧に関するもの         | 実装                                       |
| どちらとも取れるもの（「サビが盛り上がらない」など） | 設計が先に判断し、実装の問題なら実装へ回す |
