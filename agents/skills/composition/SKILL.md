# Composition

曲を作り始めるときから完成までを扱うSkill。作曲は作業ではなく創作であり、設計図を制作の指示書として使い、各段階の判断は音楽的な観点で行う。

## 作曲の姿勢

これは作業ではなく作曲である。各段階の判断は、指示の処理としてではなく、創作の判断として行う。

エージェントは作業者マインドに陥りやすい。ユーザーの指示や指摘を表面どおりに実行しようとして、曲の意図より言葉を優先し、過剰に適合した修正を行う。指摘は修正箇所の指定ではなく、曲の意図と響きのあいだにあるずれの指標である。判断するときは常に設計図の意図（何を描く曲か）に立ち返り、そこから見て正しい選択をする。過剰な適合は曲を平均化し、特徴を消す。良い曲を作ることだけが、意図に沿う道である。

このSkillのリファレンスは、あくまで参考である。ここに書かれた語彙やパターンから選ぶことが作曲ではないし、書かれていないことをするのが禁止なわけでもない。良い曲のために必要な音、進行、リズムは、この文書の外にいくらでもある。リファレンスは判断に視点と説明を与える材料であり、選択肢の上限ではない。欲しい音がここにないなら、それを作ればいい。

## 制作の流れ

曲は、抽象度の高い決定から順に作る。音源の選定は構想と設計の後に行う。音源リストを見てから曲調を決めると、音楽が音源の在庫と得意語彙に引っ張られ、似た形に収束する。順序を守ることで、音楽の判断が音の在庫より先に来る。

1. **構想** — 何を描くかを1文で定め、この曲の核を1つ（旋律・グルーヴ・響きのどれを聴かせる曲か）、エネルギーの山と谷と長さの輪郭を決める。扱うのは音楽的な言葉だけ。音色や音源の名前はまだ出てこない
2. **設計図** — 設計図で構成、和声の方向、パート間の関係（各区間の主役と、誰がどの帯域を支えるか）、主題の輪郭を書く。ビート主体ならリズムを先に鍛え、歌モノ主体なら旋律を先に鍛える、という制作の軸もここで決める。形式は [templates/blueprint-template.md](templates/blueprint-template.md)
3. **音源選定** — 設計図の各役割に対して「欲しい響き」を説明し、それに音源を割り当てる。判断材料は音域・帯域・減衰の長さ・同時発音数。最適な音源が無いとき、曲を音源に合わせて曲げるのではなく、代用できる最寄りを選ぶか、音源を作る。在庫の把握は不要な音源の作成を防ぐために必要だが、参照するのはこの段階である。「TAG」「description」は参考にしてよいが、「カテゴリ」は参考にしてはいけない。音の性質から使い方を決めること。
4. **打ち込み** — 後の要素が前の要素を参照する順に進める。この順序は依存関係の話であり、各段階を確認するときは、その時点で曲として通る形に整えておく。1パートを完成させてから次へ進むと、パート間の衝突が最後に発覚して手遅れになる。セッションの組み立ては riffra-headless

   1. 時間の器 — BPM・拍子・セクション・空クリップ
   2. 和声 — 和声イベントと伴奏
   3. 拍の骨格 — 設計図のグルーヴどおりの基本セル
   4. 低音 — キックと打点を共有し、和声を結ぶ
   5. 主旋律 — 和声・グルーヴ・低音が揃った状態で判断する。合わないときは、他パートに合わせて潰すのではなく、主旋律か和声を直す
   6. 対旋律・装飾 — 主旋律の休符と長音の空白に応答する層を置く
   7. ベロシティ — セクション構成に沿って、パートごとに階層を付ける
   8. ミックス — 音量・定位・空間を整え、通して聴ける状態にする

5. **改善ループ** — 全区間を通して、曲として成立しているかを確認する。構造の自己検査として、フレーズ末尾の休符、パート間の音域の重なり、ベロシティの幅、全員が同時に動く瞬間が頂点だけかを、ノートの列挙から検査する。修正するときは、パートの部分最適ではなく、編成（音域・密度・交代）とミックス（バランス・空間）のどちらに原因があるかを切り分けてから手を入れる。満足する出来になった段階でユーザーに完了報告をする。ここで終わりではなく、ユーザーから耳で聴いた指摘に応じて改善ループをさらに回す。指摘は過剰適合するのではなく、曲の意図に立ち返って判断する。

作曲で特に重視する観点: メロディでは、音高とリズムに加えて、休符、フレーズ境界、音域、輪郭、頂点、反復と変化を同じ重要度で扱う。**休符は一種の音符である**。AIはどうしても休符の無い平易なメロディを作りがちなので注意する。和声との関係では、旋律音の評価軸をダイアトニックへの所属よりも、コードに対する音程・拍位置・持続時間・前後の動き・解決先に置く。曲全体では、モチーフの同一性を保ちながら変化を作り、セクションごとに音域・密度・休符量・頂点を配置する。

## 品質確認

完成した素材では、次の観点をまとめて確認する。

| 観点         | 確認内容                                     |
| ------------ | -------------------------------------------- |
| フレーズ     | 境界、方向、終端、呼吸位置                   |
| リズム       | 音価の偏り、開始位置、シンコペーション、休符 |
| 音高         | 音域、テッシトゥーラ、輪郭、跳躍、最高音     |
| モチーフ     | 識別可能性、反復、変奏、断片化               |
| 和声との関係 | 安定、テンション、摩擦、クロマティックな接続 |
| セクション   | 反復、対比、発展、回帰、頂点                 |
| アレンジ     | 主役の明瞭さ、密度、音域分担、掛け合い       |

## 設計図の扱い

| 原則                 | 意味                                                                   |
| -------------------- | ---------------------------------------------------------------------- |
| 書いた項目だけが制約 | 記載のある項目だけを守る。未記入の項目はAIへの委任と解釈する           |
| 必須項目はない       | どの欄も空のまま始めてよい。曲名すら未定でよい                         |
| 形式は自由           | セクションの名前・数・区切り方は自由。表・箇条書き・文章のどれでもよい |
| 更新してよい         | 設計図は初期意図の記録である。制作過程で意図が変わったら書き戻す       |

設計図に書かれていないことを判断する必要があるときは、すでに書かれた意図に沿って制作側が選び、選んだ内容を設計図へ書き戻す。

[templates/blueprint-template.md](templates/blueprint-template.md) を曲ごとにコピーして埋める。書き上げた設計図は [out/](out/) へ1曲1ファイルで置き、制作中はそのファイルを参照する。

| 区分           | 内容                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 基本パラメータ | BPM、拍子、キー / スケール、長さ（時間と小節数）、ジャンル / スタイル、雰囲気 / コンセプト、リファレンス |
| 構成           | セクションの並び。各セクションに範囲、展開（区間ごとの具体設計）、使う音 / 楽器を書く                    |
| 備考           | 曲全体で伝えたい制約、自由記述                                                                           |
